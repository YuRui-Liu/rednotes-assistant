# RedNote 个人电商运营工作台设计

日期：2026-10-05（Asia/Shanghai）

状态：各节设计及本书面规格已获用户确认。本文不代表工具能力已实测，也不授权真实内容发布。

## 1. 目标与范围

在 Mac 本地运行，以商品为中心，支持个人管理多个小红书账号。首个完整验证商品为用户已上架的水杯；模型面向通用品类，每次研究明确指定品类。

两条入口：

1. 新品发现：品类研究 → 真实证据与候选商品 → 用户选品、找供应商并手动在千帆上架 → 商品档案。
2. 现有商品：链接导入或手动建立已上架商品档案 → 用户补充资料并确认 → 批次图文制作 → 人审 → 定时发布 → 效果记录。

第一版包括多账号、选品、商品档案、批次创作、审核、排期、浏览与互动、结果记录。不包含自动上架、采购、库存、订单、售后、团队权限及收益保证。

## 2. 商品与账号

用户于 2026-10-05 明确取消千帆 MCP 接入，原因是成熟度不足。通过商品链接导入可获取的公开信息，或手动建立档案，记录用户提供的店铺、商品 ID、链接、规格及数据来源。读取失败时保留链接并提示人工补充，不阻断建档；不存在的参数不得由模型补成事实。实拍图与卖点由用户补充确认，商品仍由用户手动在千帆上架。

商品档案包含实拍素材、已确认参数、售价及其记录时间、可证实卖点、待补充项和账号到店铺商品的关联。同一商品可对应不同店铺商品 ID。商品读取与笔记挂载是两项独立能力，分别验证。

每个账号独立维护定位、语气、登录会话、店铺关联、常用时段与每日上限。一个批次只绑定一个账号；进入制作后需要更换账号时新建批次，可以复用素材，但重新审核。

尚未关联或未验证挂载能力的账号只可创建普通种草发布任务；不得把用户已选择的挂商品任务静默降级。

## 3. 真实选品与参考检索

数据来自小红书可见页面和用户导入的后台或第三方表格。记录来源链接或文件、采集时间、数据时间范围、指标口径、原始值及缺失项。统一候选商品时保留匹配依据；不确定是否同款时不强行合并。

推荐区分：

- 潜力品：内容热度、评论痛点或需求信号较强，成交证据不足。
- 有成交证据的热销品：提供可追溯的销量或成交依据，并说明覆盖范围，不能等同平台全量榜单。

单一销量快照不得推算增长；多个同口径快照才可比较。利润、运费、退款和供货情况缺失时不编造。商品推荐报告输出证据、推荐理由、反面信号与仍需验证事项，由用户决定找货。

创作参考采用系统检索同品类笔记，加用户指定的笔记或对标账号。展示发布时间、可见互动指标及借鉴理由。参考用于分析内容结构，不照搬原文，不把高互动直接视为成交证明或因果规律。

## 4. 批次创作

默认提供 6 个选题，计划选择 3 篇；设置中可修改默认数量，创建批次时可覆盖，实际选中数量由用户决定，不强制凑满。

流程：选择商品 → 选择账号 → 生成选题与配图方案 → 用户选择和修改 → 批量生成 → 逐篇图文审核 → 排期确认。

选题卡展示目标人群、场景、标题方向、商品事实依据、参考来源、逐张图片用途、图数理由与预计成本。缺少报价时显示无法估算，不伪造费用。

配图数量不固定。结合商品特点、信息量、参考笔记结构及现有素材逐篇策划。用户可增删并修改方案；调整后重新整理逐张用途。设置提供图数上限、成本上限及偏好，实际平台限制由适配器校验。

只有选题与配图方案被确认后才执行生成。选题确认只授权内容生成，不授权发布。

GRSai 是默认批量出图服务，服务和模型可配置，每批可覆盖。记录生成配置、提示词与输入素材。切换配置只影响后续生成。Codex 先作为协作出图并导入的入口，不假设桌面出图能力可被后台服务无人值守调用。

配图参考商品实拍；审核时原图与生成图可对照。不得虚构材质、容量、保温效果或用户使用经历。生成模型不被视为天然保证商品外观准确。

部分生成失败时保留成功结果，仅重试失败部分，记录成本；超出用户批准的生成预算前再次确认。允许单篇改文案、单图重生成，保留版本。

## 5. 审核和发布授权

审核分两层：

1. 内容批准：逐篇确认不可变的图文版本、发布模式和关联商品；此时不能发布。
2. 发布授权：确认目标账号、已批准内容版本、商品关联和精确发布时间，才进入队列。

修改标题、正文、图片、发布模式或关联商品使内容批准及发布授权失效。仅调整时间保留内容批准，但必须重新确认排期。商品事实或关联信息发生影响成稿的变化时，标记相关草稿需要复核，不静默修改已审快照。

执行前程序核对批准记录、版本、账号、商品、时间和任务状态，模型不能绕过检查。批准仅适用于该动作；通过其他工具路径也不能绕开统一执行入口。

两种模式逐篇可选，批次可设默认：

- 普通种草：核实笔记真实发布并回填链接。
- 挂商品：在上述基础上核实购买入口关联正确；失败保留异常，不当作完整成功。

## 6. 排期、浏览与互动

系统按账号常用时段、每日上限及已有任务建议排期，用户逐篇调整并最终确认。无历史证据时不宣称最佳发布时间。统一显示北京时间，持久化时保存时区和绝对时间。

Mac 在线且服务正常时按排期执行；关闭页面不停止后台服务。休眠或停机错过时间进入待重新排期，不自动补发。

定时浏览以品类研究为目的，可配置关键词、对标账号、执行时段、浏览时长及每日上限，记录实际执行时长和研究证据。打开真实笔记页面、滚动、展开评论；不承诺自动化等于真人，也不承诺停留时间能规避识别或增加流量。不绕过验证码和平台限制。

点赞及留言均逐条人工批准。审核展示账号、目标笔记、具体动作、完整留言及理由。批准后在对应页面执行并回查；修改留言或目标即失效。笔记发布授权不能替代互动授权。

## 7. 界面结构与视觉

用户已确认商品中心布局和 UI Designer 精修方向：暖白底色、深色文字、克制红色强调、商品图片优先、清晰留白及响应式布局。

导航覆盖商品、选品、审核与发布、账号与设置；发布日历、浏览互动、效果数据有相应业务入口。原型中部分辅助页仅是结构说明，不代表已实现。

商品页展示资料完整度、账号批次、待审和异常事项。批次工作区包含步骤条；选题卡可多选及调整配图方案；图文审核以批次笔记列表、编辑区、预览区组织，窄屏改为顺序布局。底部保持当前步骤操作可见。通过一篇后进入下一篇；已审内容进入汇总排期。

## 9. 错误恢复

登录失效或平台验证暂停相关账号，其他账号可继续制作草稿。服务重启后恢复持久化记录；对执行中的发布或互动先核查，不直接再次执行。

发布结果不明确时进入核查状态，查找平台实际结果；仍不明确交由用户处理。任务记录唯一执行标识及尝试历史，用于防重复；不能依赖单次接口返回就宣布成功。

失败、取消、待重新审核、待重新排期、等待人工处理应明确区分。用户可取消尚未执行的任务；执行中请求取消不承诺撤回已经产生的平台操作。

## 10. 验证与验收

1. 通过真实商品链接与人工补充建立经用户确认的水杯档案；验证链接不可读时仍能手动完成建档。
2. 至少完成一次真实品类研究；推荐能追溯来源与时间，单快照不计算增长，缺成交证据仅标潜力品。
3. 完成 6 个选题中选择 3 篇，逐篇确认动态配图方案，经 GRSai 实际生成并逐篇审核。
4. 普通种草和挂商品模式分别完成用户明确批准后的真实发布，回填链接并核实商品挂载。
5. 自动化验证未批准、批准失效、版本或账号不匹配时发布和互动均被拒绝；账号会话不串用。
6. 验证部分出图失败、登录失效、休眠错过排期、服务重启、发布结果未知以及挂商品失败的处理。
7. 验证选题审核、连续图文审核、批次排期、窄屏布局及关键操作反馈。

工具能力调查先于依赖其能力的产品实现。笔记挂商品、多账号隔离、真实页面操作、GRSai 图片接口均属于明确的验证门槛；未通过时记录具体阻塞并评估适配方案，不虚称完成。不再把千帆查询作为实施或验收门槛。真实发布及互动测试仍需要用户批准对应具体内容和动作。
