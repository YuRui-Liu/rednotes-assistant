# RedNote 分阶段实现路线

> **面向 AI 代理的工作者：** 使用 executing-plans 逐任务执行；用户明确选择委派时可使用 subagent-driven-development。用复选框跟踪进度。

**目标：** 在 Mac 上完成经人工审核的小红书商品内容流水线，并用真实数据验证选品能力。

**架构：** 商品中心工作台管理账号、版本、授权和持久化任务；研究、图片与页面操作通过适配器接入。优先改造经代码核查的现有项目。

**技术栈：** 首阶段使用 Git、仓库原生工具链与 MCP 能力探测；业务技术栈由代码调查形成有证据的选型记录后锁定，不凭 README 指定。

## 当前基线

- 已批准规格：`docs/superpowers/specs/2026-10-05-rednote-design.md`。
- 已批准视觉：本地 `.superpowers/brainstorm/73611-1791184983/content/batch-flow-v4-polished.html`。
- 仓库目前仅有规格、忽略规则和本计划，没有业务代码。
- 2026-10-05 用户取消千帆 MCP 接入。商品改为链接导入与手动补充；小红书发布和挂商品能力继续验证。
- 文案 LLM 的接口、模型与凭据必须在连接验证阶段确认；不能将当前聊天模型自动视为后台服务接口。

## 实施顺序与阶段出口

| 阶段 | 交付 | 验证出口 |
| --- | --- | --- |
| 0 能力与复用调查 | 仓库版本、许可证、代码路径、工具能力矩阵、底座决策 | 关键能力有代码证据或明确阻塞，不用 README 代替实测 |
| 1 商品、账号与授权核心 | 本地数据持久化、商品链接导入及手动建档、账号映射、不可变图文版本与审批 | 未批准、过期版本、跨账号操作均被拒绝；重启不丢档案 |
| 2 批次创作工作区 | 已批准视觉落地、默认 6 选 3、参考来源、逐图策划、GRSai 与文案生成 | 实际生成一批水杯图文；单项失败可恢复，修改令批准失效 |
| 3 定时发布 | 排期建议、最终授权、串行页面执行、普通与挂商品模式、回查 | 两种模式在具体内容获批后实测；不重复发、不静默降级 |
| 4 真实选品 | 页面数据、表格导入、同款归一、快照与证据报告 | 一个真实品类报告可逐条追溯，不编造增长及利润 |
| 5 浏览互动与复盘 | 定时阅读、逐条互动审核、页面执行、效果快照 | 未批准点赞留言不能执行；异常暂停对应账号；数据有口径和时间 |
| 6 综合验收 | 跨账号隔离、重启恢复、错误演练、使用文档 | 规格第 10 节全部覆盖；缺项明确列出，不宣布完整跑通 |

阶段 4 的数据采集契约在阶段 0 调查，不能直到界面完成后才发现没有真实数据来源。阶段 2 使用系统检索和用户指定参考；阶段 4 增加商品候选排序与历史趋势，不阻断现有商品创作路径。

## 计划拆分规则

立即执行的详细计划为 `2026-10-05-rednote-capability-validation.md`。它产出下一阶段可精确引用的源码路径、版本和契约。

每阶段开始前，依据已核查代码生成该阶段详细计划，包含实际文件路径、失败用例、运行命令、最小实现步骤与验证出口。不把本路线表冒充全产品可直接执行的代码计划，也不提前编造上游接口。

## 全程约束

- 真正发布及互动需批准具体内容和动作；规格批准不是发布批准。
- 不安装或改造多个完整应用来重复保存同一业务状态。
- 不伪造销量、历史增长、模型价格或执行成功。
- 出图费用先按用户配置预算控制；接口验证不随意发起付费生成。
- 本地真实数据、Cookie、API Key、店铺经营信息不进入 Git。
- 继承用户 Weaver 规则：Shell 内容写入前解析目标 Git 根和忽略状态；非 Shell 编辑由 hook 记录。
