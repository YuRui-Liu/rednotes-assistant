# 自营店铺商品同步实现计划

用户已确认：增加点击同步按钮，从自己的店铺读取商品，预览后导入；按店铺 ID + 商品 ID 去重，保留手工资料，新档案待核对。不做定时同步或平台上下架写操作。

## 实现顺序

- [x] `tests/shop-sync.test.mjs`：先验证重复导入、跨店铺隔离、手动资料保留、无效快照整体拒绝、同步状态更新和未返回商品保留。
- [x] `server/shop-sync.mjs`：独立的商品快照校验和事务导入；远端数据与本地创作档案分开保存，更新远端快照不改已审核的创作事实。
- [ ] 店铺连接：依据用户已有登录或开放平台授权选择实际读取方式。分页不完整、身份不明、授权失效时拒绝导入，不能解释成空店铺。当前内容账号连接器没有店铺查询端点。
- [x] `server/services.mjs`：接入读取预览及导入路由，导入只能引用后端已经读取的快照。
- [x] `public/app.js`、`public/shop-sync.js`：商品页入口、选择账号、读取结果与状态、导入反馈及资料来源展示。
- [x] 运行 `node --test tests/shop-sync.test.mjs`、`npm test`；浏览器检查同步流程。真实店铺读取需要有效店铺授权，单元测试不作为真实店铺验收。

## 数据规则

`shopSource` 保存 `shopId`、`productId`、店铺名称、账号 ID、远端名称/链接/图片/参数、商品状态和读取时间。首次导入创建 `confirmed:false` 档案；重复导入只更新该来源快照，本地 name/facts/images/url 不覆盖。平台未返回的商品不推断为删除或下架。所有商品先完整校验，再在 SQLite 事务中落库。

状态仅接受 `on_sale`、`off_shelf`、`sold_out`、`pending`、`unknown`；没有可靠状态证据时显示状态未知。商品图片标记为店铺图片，不能声称已核对实拍。
